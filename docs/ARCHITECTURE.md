# V1 架构

## 模块与依赖

`src/us_watchlist/` 是 Python 模块化单体。表中依赖是允许直接 import 的本项目层；
各层内部可以拆分子模块，内部依赖也必须无环。包初始化文件用于文档说明。

| 层 | 职责 | 可依赖 |
| --- | --- | --- |
| `domain` | 不可变 US 业务值、时段、行情、来源、策略版本与共享投影契约 | 无 |
| `universe` | 点时股票池资格、重复证券、输入可用性 | `domain` |
| `market_data` | 交易日历及已完成行情、延迟、重复、缺口和价格基准校验 | `domain` |
| `strategies` | 内存策略接口，未来承载各自版本化的 B、C 及新策略 | `domain` |
| `research` | 价格结构代理、回踩量能、同阶段坐标及参考计划的内存计算 | `domain` |
| `tracking` | 烟测输入覆盖、独立研究模拟状态转换及按样本分组的已实现 R | `domain` |
| `reporting` | HTML 只读投影 | `domain` |
| `integrations` | 输入、行情、交易日历和产物读写边界 | `domain` |
| `app` | CLI 和流程编排，根据任务选择适配器、调用计算与单一写入方 | 以上各层 |

`configs/` 管版本可控配置，`tests/` 保存工程回归及架构检查，`docs/` 保存治理事实与决策，
`.github/workflows/` 保存跨平台 CI 和独立日报编排。

## V1 烟测数据流

1. `app` 通过 fixture 适配器读取 US 合成 TOML。输入包括显式会话、股票池生效日、价格基准，及
   两份快照各自的来源、身份、UTC 可用时间。
2. `universe` 在决策截止时刻核对股票池并返回有效证券；`market_data` 校验时段完成和数据可用性，
   为该股票池提供同一时段的 OHLCV。缺行情时保留资格与缺口，烟测报告如实展示。
3. `app` 将已校验输入分别交给 `tracking` 和 `research`，再把只读观察与描述统计交给 `reporting`。
   未来的策略获取同一受检快照的历史序列。跟踪在信号发出后记录该版本与当时输入身份，
   后续收益增量独立附着。研究晋级须经过代码审阅；日报消费各层已形成的事实。
4. `app` 通过本地适配器发布 HTML。V1 以用途、市场、交易日和时段唯一标识烟测产物。
   完整写入同目录的临时文件后原子发布；相同内容重试复用，冲突报错，先写成的文件保留。
   同一目录需支持硬链接，例如 NTFS 或 Linux CI 文件系统。真实跟踪存储以后依据写入语义选型。

## 时点和时段

- `trading_date` 是由日历或交易场所规则赋予的交易日标签。开始、结束、数据可用和决策截止使用
  带 UTC 偏移的时间戳。价格快照表示完整的一个时段，必须在该时段结束后可用并且当时已可获得。
- `regular`、`pre_market`、`after_hours`、`ibkr_overnight` 分别建模。夜间窗口可跨自然日。
  合成 fixture 显式给出时间窗口。实际 IBKR 夜间交易日归属、DST、假日与短市由未来适配和日历测试定义。
- 原始与复权价格保留显式基准。未来跨日策略必须约定同一基准、公司行动可见时点、可交易报价与
  可比较价格的关系。证券符号、行情、研究和执行记录始终处在 US 项目边界内。
- 数据中台接入应分辨上游 IWB seed、候选输出和正式策略池的语义；提供可追溯的 US 时点快照。
  对外映射、生产缓存、纸面或 IBKR 账户状态均在集成边界引入。

## 常规时段离线 B+C

`integrations` 从数据中台日报读取实际 US Candidate，核对完整 IWB 审计与发布名单，
用归档上传时间作为输入可用时间。Yahoo Chart 采集将原响应和 XNYS 会话归档到本地，
按逐票、整批 SHA-256 绑定到离线清单。历史点时观察与外部声明的点时回放使用不同输入口径。
`app` 通过 `universe` 和 `market_data` 核验资格和行情，将只读快照交给 `strategies`。
编排层独立调用 B 和两套 C 版本，形成各自的状态和逐股记录。报告聚合这些只读结果，
各策略结果独立嵌入同一 HTML，单一写入方按内容身份发布。详细契约见
[共用输入和 B 形态](B_OFFLINE.md)与 [B+C 离线日报](BC_OFFLINE.md)。

联合日报的研究计算消费已匹配的规则结果及同一验证行情的逐股连续尾段。
`research` 使用已有 B 突破、C 前高与支撑锚点生成独立的只读投影。
`reporting` 读取该投影展示研究卡片，并在原有筛选记录之外嵌入研究 JSON。
行情采集、资格筛选、候选身份与归档写入仍由各自原入口负责。见 [B+C 参考研究](BC_REFERENCE_RESEARCH.md)。

联合工作台通过独立的 `Workbench` 契约读取已验证常规日线、当次股票池与原研究结果。
`research` 汇总市场宽度、板块风格与 B 候选分层，`reporting` 生成离线图表和交互。
中文简称目录为纯内存数据，IWB 的官方英文名、板块及百分数权重在适配边界透传。
可选邮件精选从已验证的原附件读取，日报收据及嵌入审计的契约保持兼容。

## 防回归

测试静态核验项目 import 方向和模块环；计算层外部 import 采用纯计算标准库允许表，约束直接 I/O
与动态加载。测试覆盖未来输入、半成品行情、重复行、时段独立、跨市场拒绝和并发发布。
Git 检查拒绝暂存的忽略项、典型运行目录与产物格式。代码审阅负责策略语义和间接 I/O，
数据契约与文件系统权限共同承担未来生产隔离。

## IWB 正式基础池与共用行情

`integrations` 从 iShares 官方端点冻结日期、原件及收据。`app` 选取目标交易日可用的本地版本，调用共同 XNYS 会话适配器、Yahoo Chart 采集和 `market_data` 校验。基池成员、上市状态、行情完整性及策略匹配保留各自证据。独立 B 与 C 复用离线评估和 HTML 投影。原 Candidate 契约保留供历史观察复现。日报版本冻结当次输入和策略结果，出错时保留已有证据。见 [IWB 基础池与日报](IWB_DAILY.md)。

Actions 编排层恢复私有仓库的已验证归档，由手动和定时作业共用的发布组串行上传。恢复需通过归档内容 SHA 和预期文件名单，已发布报告再校验输入与报告 SHA。失败证据有独立运行身份和有界保留期。CI 运行合成测试及归档传输验证。定时由仓库变量控制，运行时复核目标会话和 Yahoo 收盘依据。见 [自动化契约](IWB_AUTOMATION.md)。

VPS 触发器通过 GitHub API 提交带纽约会话日期的请求。Actions 对两个定时入口使用同一收盘校验和串行发布组，
按已验证的日报归档抑制定时重发。手动补发保持显式入口。
VPS 使用独立的 GitHub App，按次申请仅限本仓库的 Actions 安装令牌。systemd 负责向触发器提供私钥。

通知为独立可选的外部交付边界：`app` 在验证完成的日报收据后投影中文邮件摘要，`integrations` 通过 SMTP 发送原 HTML 附件；归档成功后才发送邮件。工作流使用独立后置作业，在日报作业失败时经 Bark 发送运行链接，避免把通知结果写回策略研究或改变规范日报身份。

## IWB 研究模拟账本

`app` 复用日报收据验证、官方股票池、Yahoo 价位基准以及 XNYS 日历，将同一归档的机器记录对照后构建
每日证据。`tracking` 接收验证后的内存证据，先处理已有计划和持仓，再添加新信号，按原始入场风险计算 R。
`integrations` 以研究模式、协议、起始日期和政策确定账本身份，将每个会话的输入与前序摘要一起一次性发布。
复原需要从指定首日到目标日的连续会话。`reporting` 将模拟仓位投影插入 SHA 校验后的原日报 HTML，
组合视图单独发布，保留原日报的逐股机器记录及账本身份。旧模拟视图可显式恢复。
前瞻模式在离线入口拒绝执行。归档、参数和开放缺口的处理见 [研究模拟持仓](IWB_PAPER.md)。
